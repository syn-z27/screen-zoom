# ScreenZoom

macOS のアクセシビリティにある「修飾キー＋スクロールで画面全体をズーム」を Windows で再現する常駐ツール。

**Ctrl＋Shift＋ホイール**で操作する。

## 機能

- **Ctrl＋Shift＋ホイール上下**で画面全体を拡大 / 縮小（1 ノッチ約 1.12 倍、最大 20 倍、等倍付近で 1.0 にスナップ）
- ノートPCの**タッチパッドの二本指スクロール**にも対応（指を上に動かすと拡大）
  - マウスとタッチパッドは Raw Input で見分ける。タッチパッドは判定待ちのため 40〜50ms ほど遅れてズームする
- ズームはカーソル位置を中心に行い、カーソルは画面上の同じ位置に見えたままになる
- 拡大中は、カーソルが表示領域の**端に達したときだけ**、越えた分だけ表示領域が移動（macOS の「ポインタが端に達したときのみ」相当）
- Windows 標準の Magnification API を使用するため、拡大中もクリック位置はずれない
- 管理者権限で動作するため、タスクマネージャーや `.msc` の管理ツールの上でもズームできる
- タスクトレイ常駐（右クリックメニュー）
  - 有効 / 無効の切り替え（アイコンのダブルクリックでも可）
  - ズームをリセット
  - Windows 起動時に実行（タスクスケジューラにタスク `ScreenZoom` を「最上位の特権で実行」として登録。インストール済みの exe のみ）
  - 終了（終了時・ログオフ時は等倍に戻す）

## 動作環境

- Windows 10 (1703 以降) / Windows 11、64 ビット
- .NET Framework 4.x（Windows に標準搭載）
- 管理者権限を持つユーザー

## ビルド

追加インストール不要。.NET Framework 付属の C# コンパイラ `csc.exe` を直接呼び出す。

```bat
build.bat
```

同じフォルダに `ScreenZoom.exe` が生成される。起動中の場合は exe を上書きできないため、トレイから終了してからビルドする。

## インストール

```bat
install.bat
```

`ScreenZoom.exe` を管理者しか書き込めない `C:\Program Files\ScreenZoom\` にコピーして起動する（UAC の確認画面が出る）。起動中の ScreenZoom は自動で終了する。ソースを更新したときは `build.bat` → `install.bat` の順に実行する。

## 使い方

`C:\Program Files\ScreenZoom\ScreenZoom.exe` を起動すると、管理者権限の確認画面（UAC）のあとにタスクトレイに虫眼鏡アイコンが表示される。Ctrl＋Shift を押しながらマウスホイールを回す（タッチパッドなら二本指で上下に動かす）。

画面が操作できなくなったときなど、トレイから終了できない場合は `stop.bat` を実行すると強制終了できる（管理者権限で動いているため、UAC の確認画面が出る）。

トレイメニューの「Windows 起動時に実行」で自動起動を有効にすると、サインイン時は UAC の確認画面なしで起動する。

## セキュリティ

ScreenZoom は管理者権限で動き、自動起動のタスクは UAC の確認なしに管理者権限で exe を起動する。一般ユーザーが書き換えられる場所の exe を自動起動に登録すると、他のプログラムが exe を置き換えるだけで管理者権限を得られてしまうため、次のようにしている。

- 自動起動は `C:\Program Files\` 配下にインストールした exe からのみ登録できる（ビルドしたフォルダの exe からは登録できない）
- 起動時に、一般ユーザーが書き換えられる場所の exe を指す自動起動のタスクが見つかった場合は解除し、通知する。以前の版のレジストリ（Run キー）の自動起動も解除する（インストール済みの exe ならタスクスケジューラへ移行する）
- `Magnification.dll` などの DLL は System32 からのみ読み込み、`schtasks.exe` などのコマンドは System32 のフルパスで実行する（exe やバッチと同じフォルダに置かれた偽物を使わない）
- 自動起動のタスク定義はユーザーの TEMP ではなくインストール先に一時的に書き出す

## 制限事項

- Ctrl＋Shift を押している間は画面全体を透明なウィンドウで覆ってスクロールを受け取るため、その間のクリック（Ctrl＋Shift＋クリックの範囲選択など）はアプリに届かない
- キーボード配列を複数入れていて Ctrl＋Shift に配列の切り替えが割り当てられている場合、ズーム後にキーを離したときに配列が切り替わる可能性がある
- マルチモニター環境での動作は未確認

## ファイル構成

| ファイル | 内容 |
| --- | --- |
| `ScreenZoom.cs` | 本体ソース（低レベルマウス/キーボードフック＋Raw Input＋Magnification API） |
| `ScreenZoom.manifest` | 管理者権限で実行するためのマニフェスト |
| `build.bat` | ビルドスクリプト |
| `install.bat` | `C:\Program Files\ScreenZoom\` にインストールするスクリプト（自動で管理者権限に昇格） |
| `stop.bat` | ScreenZoom を強制終了するスクリプト（自動で管理者権限に昇格） |
